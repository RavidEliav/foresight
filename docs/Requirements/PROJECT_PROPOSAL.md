# Project Proposal: Foresight
### Multi-Agent Semiconductor Yield Intelligence on SECOM

**Course:** AI Developers Course · Final Project  **Submitted:** 18 Nov  **Author:** Ravid Eliav  **Deploy:** Railway (`main` + `dev`)  **Track:** Alternative Path, using the official CrewAI Flow structure in a semiconductor domain

| Section | Content |
|---|---|
| **Problem** | Wafer fabs record hundreds of sensor and process signals per production run, yet yield failures are rare and their causes are hidden among those signals. Engineers spend a lot of time checking data quality, finding which signals separate failing runs, and writing up findings. A data quality problem or an unsupported root-cause claim can lead to costly wrong decisions. |
| **Dataset** | **SECOM (UCI ML Repository):** 1,567 production runs × 590 anonymized numeric sensor features, a pass/fail label (`-1`/`1`), and a timestamp per run. Target: **fail**, which is 104 runs (≈6.6%). Limitations: heavy class imbalance, many missing and constant columns, anonymized feature names (no physical meaning), a single fab and a limited time window. WM-811K is kept only as a future extension. |
| **Project idea** | **Foresight** is a CrewAI Flow that coordinates four agent crews, behaving like an industry AI product team. Data Analyst Crew → Data Scientist Crew → Investigation Crew → Engineering Report Crew. Validation gates between stages follow a formal Data Contract. |
| **What will be developed** | (1) Python tools for loading, cleaning, statistics, anomaly detection, and modeling. (2) A `dataset_contract.json` plus validation gates. (3) A CrewAI Flow with ≥3 agents per core crew and typed state, logging, and graceful failure. (4) A Streamlit app, **deployed on Railway** in two environments, `main` (stable) and `dev` (testing), each auto-deployed from its matching Git branch, where the engineer runs the pipeline and browses data quality, EDA, model results, hypotheses, and the final report. (5) A GitHub repo with a feature → `dev` → `main` PR workflow, README, and automated tests: unit, integration and **Playwright E2E** tests on every PR into `dev` and `main`, plus smoke and E2E tests against the live app after every deployment. |
| **Goal** | Show a reproducible, end-to-end AI workflow that turns raw fab data into (a) validated, documented data, (b) a fail-prediction model that beats a naive baseline on imbalance-aware metrics, and (c) an engineer-ready report that separates measured facts from AI hypotheses. |
| **Method** | **Validation:** contract checks for columns, types, missing values, and allowed label values. ERRORs stop the flow; WARNINGs are flagged. **Statistics/EDA:** distributions, fail rate over time, pass-vs-fail signal comparison. **Classification:** ≥2 variations (e.g., balanced Logistic Regression vs Random Forest/Gradient Boosting) evaluated with PR-AUC, fail-recall, F1, and balanced accuracy, plus permutation importance. **Anomalies:** IsolationForest and SPC/z-score limits. **Agents:** Python tools compute every number; LLM agents interpret, form hypotheses, and write. Temperature 0 and fixed seeds keep runs reproducible. |
| **Capabilities & scope** | **In:** SECOM ingestion, Data Contract gates, EDA report, model comparison and model card, anomaly investigation, engineering report, Streamlit UI **deployed on Railway (`main` + `dev`)**, CI, Playwright E2E and post-deploy smoke tests, run logs and manifest. **Stretch:** RAG & embeddings (similar-run search, a cited knowledge base for investigation, an "Ask Foresight" chat over the run's reports), Supabase storage, SHAP, a live "Predict" page, a Flask `/predict` API. **Out:** wafer-map image modeling, real-time fab integration, confirmed root-cause analysis. |
| **Expected output** | After one run the engineer receives: `validation_summary.json`, `clean_data.csv`, `eda_report.html`, `insights.md`, `dataset_contract.json`, `features.csv`, `model.joblib`, `evaluation_report.md`, `model_card.md`, `investigation.md`, and a final **`engineering_report.md`** (detections, evidence, key abnormal parameters, labeled hypotheses with confidence, recommended next steps), all viewable in the Streamlit app at the public Railway `main` URL. |

**Final deliverables (Dec 4 / Dec 9):** GitHub repository · 10–12 slide business presentation · ≤5-min demo video.
